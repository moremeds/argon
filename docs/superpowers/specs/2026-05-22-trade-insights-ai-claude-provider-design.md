# Trade Insights AI — Claude Provider (Side-by-Side Comparison)

**Date:** 2026-05-22
**Status:** Design draft — awaiting user review
**Related PR (predecessor):** [#64](https://github.com/moremeds/unusual-whales/pull/64) — v4 swing-HOLD prompt + dealer-regime/vanna-charm evidence
**Related memories:** [[swing-hold-vs-swing-expiry]], [[deliver-results-through-the-real-worker-path]]

## 1. Problem

The Trade Insights AI feature currently runs a single AI provider (local Codex CLI) over the v4 swing-HOLD prompt for a given stock. The operator can see *one* analysis per ticker but has no way to compare what a different AI provider would say about the same input. Two providers running the same prompt give the operator a sanity check — if Codex and Claude both pick a long-calls 30-DTE thesis, that's higher conviction than if they disagree.

## 2. Goal

Run the same v4 swing-HOLD prompt and same JSON schema through **both** Codex and Claude on every Run click. Surface both results in the existing stock-detail Trade Insights AI panel as **two tabs** (`Codex | Claude`) with per-provider status. Keep the prompt, schema, validator, markdown renderer, and Pydantic outcome model **identical across providers** so the comparison is "same input, different model" by construction.

## 3. Non-goals

- Not adding a third provider in this PR (the design extends cleanly to a third, but YAGNI for v1).
- Not implementing a semantic-diff "comparison" tab — tabs alone are the surface. The operator reads both manually.
- Not changing the prompt, schema, validator, renderer, or any deterministic Trade Insights logic. v4 stays v4 for both providers.
- Not implementing per-provider Retry buttons in v1 — clicking Run cache-hits the succeeded provider and re-enqueues the failed one, which covers the use case without new code paths.
- Not building bare-mode/API-key auth for Claude in v1 — OAuth keychain via subscription is the only supported auth path. Bare-mode is a tracked follow-up env var (`TRADE_INSIGHTS_AI_CLAUDE_USE_BARE`).

## 4. User-facing behavior

### 4.1 Run click

User clicks the single **Run** button on the Trade Insights AI panel of `/stock/<TICKER>`. The API enqueues one row per enabled provider; the response contains one stub per provider (with each provider's own `analysis_id`, `status`, `reused`, `model`). The UI immediately:

- For any stub with `reused: true` + `status: 'succeeded'` → render that provider's tab from `/latest` (already on the page from initial fetch).
- For any stub with `reused: false` or non-terminal status → start a 3-second polling loop on its `analysis_id` until terminal, then refresh `/latest`.

### 4.2 Tabs

Two tabs in the panel: `[Codex ●] [Claude ◐]`. Each tab shows:

- **State dot** indicating that provider's row status (`●` succeeded, `◐` running, `✕` failed, `○` no data, `—` provider disabled).
- **Body**: existing markdown + structured outcome detail rendering. Unchanged from current single-provider rendering.
- **Footer**: `Generated by <provider> (<resolved-model>) · prompt v4 · <produced_at> · <duration>s`.

When a tab is in `failed` state, the body shows the formatted error message (lifted `ERROR:` line first, then tail).

### 4.3 Cache-mixed render

Common case during the day: same ticker re-clicked. Per-provider cache reuse:

- Same input hash + same prompt v4 + same Codex model → Codex reuses; status=succeeded, reused=true.
- Same input hash + same prompt v4 + same Claude model → Claude reuses; status=succeeded, reused=true.
- Either side independently misses cache (e.g., `TRADE_INSIGHTS_AI_CLAUDE_MODEL` changed) → that side fresh-runs while the other reuses.

## 6. Database migration — `053_trade_insights_ai_provider_column.sql`

```sql
SET search_path TO uw_scan, public;

ALTER TABLE uw_scan.trade_insight_ai_analyses
    ADD COLUMN IF NOT EXISTS provider TEXT NOT NULL DEFAULT 'codex';

ALTER TABLE uw_scan.trade_insight_ai_analyses
    DROP CONSTRAINT IF EXISTS trade_insight_ai_analyses_provider_check;

ALTER TABLE uw_scan.trade_insight_ai_analyses
    ADD CONSTRAINT trade_insight_ai_analyses_provider_check
        CHECK (provider IN ('codex', 'claude'));

DROP INDEX IF EXISTS uw_scan.idx_trade_insight_ai_analyses_succeeded_reuse;
CREATE UNIQUE INDEX IF NOT EXISTS idx_trade_insight_ai_analyses_succeeded_reuse
    ON uw_scan.trade_insight_ai_analyses (
        ticker, analysis_input_hash, prompt_version, model, provider
    )
    WHERE status = 'succeeded';

DROP INDEX IF EXISTS uw_scan.idx_trade_insight_ai_analyses_active_reuse;
CREATE UNIQUE INDEX IF NOT EXISTS idx_trade_insight_ai_analyses_active_reuse
    ON uw_scan.trade_insight_ai_analyses (
        ticker, analysis_input_hash, prompt_version, model, provider
    )
    WHERE status IN ('queued', 'running');

CREATE INDEX IF NOT EXISTS idx_trade_insight_ai_analyses_provider_queue
    ON uw_scan.trade_insight_ai_analyses (provider, status, requested_at);

COMMENT ON COLUMN uw_scan.trade_insight_ai_analyses.provider IS
    'AI provider that produced this analysis: codex or claude. '
    'Each Run enqueues one row per enabled provider; per-provider cache reuse '
    'is enforced by indexes keyed on (ticker, analysis_input_hash, '
    'prompt_version, model, provider).';
```

**Backfill safety:** `DEFAULT 'codex'` on `ADD COLUMN` is metadata-only in PostgreSQL 11+ — no full table rewrite. All historic rows were Codex.

**Index design:** putting `provider` LAST in the key preserves the leftmost-prefix `(ticker, analysis_input_hash, prompt_version, model)` which is used by existing repository queries — they remain efficient without modification.

When a `*_ENABLED` flag is `false`, the API skips enqueueing that provider and `POST` response omits it from `analyses[]`. The UI tab renders a `—` empty state.

## 8. Worker roles — provider-pinned

Four total AI workers, hard-partitioned by provider.

| Role | Behavior | Default count | Heartbeat key |
|---|---|---|---|
| `ai-codex` | Claims only `provider='codex'` rows | 2 | `trade_insights_ai_tick_codex` |
| `ai-claude` | Claims only `provider='claude'` rows | 2 | `trade_insights_ai_tick_claude` |
| `ai` *(legacy)* | Claims any provider | — | `trade_insights_ai_tick` |

`Repository.claim_next_trade_insight_ai_analysis()` gains a `provider: str | None = None` filter parameter. When set, the WHERE clause includes `AND provider = %s`. The `idx_trade_insight_ai_analyses_provider_queue` index covers this filter cheaply.

`worker/scheduler.py` reads `UW_SCAN_WORKER_ROLE`:

```python
if role == "ai-codex":
    sched.add_job(lambda: trade_insights_ai_tick(settings, provider_filter="codex"), ...)
elif role == "ai-claude":
    sched.add_job(lambda: trade_insights_ai_tick(settings, provider_filter="claude"), ...)
elif role == "ai":
    sched.add_job(lambda: trade_insights_ai_tick(settings, provider_filter=None), ...)
```

`scripts/dev.sh` boots 4 workers (2 of each role) in addition to the existing UW + massive + WebSocket processes.

**Isolation property:** if Codex CLI hangs (e.g., quota-block returning slowly), the Claude pool keeps full throughput on the user's other tickers. Trade-off: idle capacity when one queue is empty. For the actual workload (one Run = one row per provider), every Run produces identical depth in each pool, so this is acceptable.

## 9. Claude runner — `worker/jobs/trade_insights_claude_runner.py`

### 9.1 CLI invocation

```bash
claude --print \
  --tools "" \
  --disable-slash-commands \
  --strict-mcp-config \
  --mcp-config '{"mcpServers": {}}' \
  --no-session-persistence \
  --output-format json \
  --json-schema <inline JSON schema string> \
  --add-dir <tmpdir> \
  --model <resolved model alias>
```

Stdin: the v4 swing-HOLD prompt (built by the shared `build_trade_insights_ai_prompt`).

**Why each flag:**

- `--print` (`-p`): headless mode, single response then exit.
- `--tools ""`: disable all Claude tools (no Bash/Read/Edit/WebFetch/etc.). The Claude subprocess is pure prompt-in/JSON-out — no file or network side effects.
- `--disable-slash-commands`: disable skill execution. Belt-and-braces alongside `--tools ""`.
- `--strict-mcp-config --mcp-config '{"mcpServers": {}}'`: lock MCP to an empty server registry. **Verified in pre-flight:** bare `'{}'` is rejected with `Invalid input: expected record, received undefined` — the schema requires the `mcpServers` key.
- `--no-session-persistence`: no transcript persistence to disk.
- `--output-format json`: stdout becomes a single JSON **array** of events (init / assistant / result). NOT a single envelope object. See §9.2 for parsing.
- `--json-schema <schema>`: enforces the output shape (same schema as Codex). Claude will refuse to emit non-conforming JSON.
- `--add-dir <tmpdir>`: confines workdir to an empty tmp dir. Without this, `CLAUDE.md` auto-discovery could load project context.
- `--model <alias>`: optional; passes through `TRADE_INSIGHTS_AI_CLAUDE_MODEL`.

**Why NOT `--bare`:** `--bare` requires an API key (skips keychain OAuth). We want the user's existing Claude Code subscription, not new API-key billing. The flag combo above is the security-equivalent for OAuth mode: tools off, skills off, MCP off, session-persistence off. **However**, `ANTHROPIC_API_KEY` in the parent env overrides OAuth keychain even without `--bare` — verified in pre-flight, `apiKeySource` reports `ANTHROPIC_API_KEY`. The runner's `_runner_child_env` allow-list strips `ANTHROPIC_API_KEY` so Claude falls back to OAuth keychain.

### 9.2 Output parsing

`claude --print --output-format json` emits stdout as a JSON **array of events**, not a single envelope. The runner walks the array to extract the init event (for the resolved model) and the final result event (for the structured output + the `is_error` flag — `is_error: true` can coexist with `subtype: "success"` for API failures like quota exhaustion, verified in pre-flight).

```python
events = json.loads(completed.stdout)
if not isinstance(events, list):
    raise TradeInsightsAiRunnerError("expected JSON array of events")

init_event = next(
    (e for e in events
     if isinstance(e, dict)
     and e.get("type") == "system"
     and e.get("subtype") == "init"),
    None,
)
result_event = next(
    (e for e in reversed(events)
     if isinstance(e, dict) and e.get("type") == "result"),
    None,
)
if result_event is None:
    raise TradeInsightsAiRunnerError("no result event")
if result_event.get("is_error") is True:
    raise TradeInsightsAiRunnerError(
        f"API error (status={result_event.get('api_error_status')}): "
        f"{result_event.get('result')}"
    )
if result_event.get("subtype") != "success":
    raise TradeInsightsAiRunnerError("non-success subtype")

parsed = json.loads(result_event["result"])
resolved_model = (
    (init_event or {}).get("model")
    or result_event.get("model")
    or (configured_model or "claude-default")
)
return RunnerResult(outcome=parsed, resolved_model=resolved_model)
```

**Why the init event matters:** the canonical resolved model (e.g. `claude-opus-4-7` when `--model opus` was the alias) lives on the init event. The result event also typically carries the model, but the init event is the most reliable source.

### 9.3 Resolved model capture (the "nice to have")

`envelope["model"]` exposes the canonical Claude model ID even when the operator passed an alias. e.g. `--model opus` → `envelope["model"] == "claude-opus-4-7"`. The runner persists the canonical ID so:

- Cache key correctness: future Runs match the canonical ID, not the alias.
- UI footer shows the actual model used (`Generated by claude (claude-opus-4-7) · prompt v4 · ...`).
- Alias rollover (e.g., `opus` resolving to a newer minor version next week) becomes visible in the cache — no silent stale-cache reuse.

Codex runner gets the same treatment if Codex CLI exposes resolved-model metadata (to be verified during implementation; falls back to configured value otherwise).

### 9.4 Shared error formatter

`_format_runner_failure(stderr, stdout, tail_chars=1500)` is moved from `trade_insights_ai.py` into the shared runners module. Both Codex and Claude failures use it:

```
codex exec failed with exit 1: [errors] ERROR: You've hit your usage limit... | [tail] ...
claude --print failed with exit 1: [errors] ERROR: Authentication failed... | [tail] ...
```

This is the regression-tested format from commit `fb6ab98` (the NVDA-quota diagnostic fix); both runners benefit from the lifted `ERROR:` line first / tail second formatting.

## 10. API contract changes

### 10.1 POST `/api/stock/{ticker}/trade-insights/ai-analysis`

```json
// Response 202
{
  "analyses": [
    { "provider": "codex",  "analysis_id": "...", "status": "queued",    "reused": false, "model": "codex-default" },
    { "provider": "claude", "analysis_id": "...", "status": "succeeded", "reused": true,  "model": "claude-opus-4-7" }
  ]
}
```

- One stub per **enabled** provider. Disabled providers are omitted (not included with a "disabled" status — keep the response clean).
- Each stub independently reports `status` and `reused`.

### 10.2 GET `/api/stock/{ticker}/trade-insights/ai-analysis/latest`

```json
// Response 200 — always 200, even when both are null
{
  "codex":  { "analysis_id": "...", "status": "succeeded", "provider": "codex",  "model": "codex-default",   "prompt_version": "trade-insights-ai-v4", "produced_at": "...", "outcome": {...}, "markdown": "...", "error_message": null } | null,
  "claude": { "analysis_id": "...", "status": "succeeded", "provider": "claude", "model": "claude-opus-4-7", "prompt_version": "trade-insights-ai-v4", "produced_at": "...", "outcome": {...}, "markdown": "...", "error_message": null } | null
}
```

Returns 200 with both keys null when no succeeded rows exist (instead of 404 — the page renders the empty Run state).

### 10.3 GET `/api/stock/{ticker}/trade-insights/ai-analysis/{analysis_id}`

Path unchanged. Response gains `provider` and `model` fields. Used by the UI to poll a specific provider's in-flight row independently.

### 10.4 Pydantic models

Per the [API model refactor preserves contract identity](.) rule, all public model names in `uw_scan.models` stay stable. New additions:

- `TradeInsightAiProvider` — `Literal["codex", "claude"]`
- `TradeInsightAiAnalysisStub` — `{provider, analysis_id, status, reused, model}`
- `TradeInsightAiAnalysisEnqueueResponse` — `{analyses: list[TradeInsightAiAnalysisStub]}`
- `TradeInsightAiLatestPair` — `{codex: TradeInsightAiAnalysis | None, claude: TradeInsightAiAnalysis | None}`

Existing `TradeInsightAiAnalysis` gains two non-breaking fields (`provider: TradeInsightAiProvider`, `model: str`).

### 10.5 Backwards compatibility

**Hard break — no shim.** The only consumer is `web/lib/api.ts`. Two files in `web/` change; no external integrations, no mobile app. A shim would create permanent ambiguity ("which provider does the top-level `analysis_id` belong to?") for no benefit.

### 11.2 State machine per tab

| State | Visual | Source |
|---|---|---|
| `succeeded` | `●` filled dot, full body | `latest[provider]` has a row, status='succeeded' |
| `running` | `◐` half-filled dot + spinner; prior `latest` body dimmed underneath | `pending[provider]` set, polling not yet terminal |
| `failed` | `✕` red X; error_message body with retry hint | terminal status='failed' |
| `empty` | `○` open dot; "Click Run" prompt | `latest[provider] === null` AND `pending[provider] === null` |
| `disabled` | `—`; "Provider disabled" placeholder | `*_ENABLED=false` (server omits stub from POST response) |

### 11.3 Polling discipline

- One `setInterval` per pending `analysis_id` — independent per provider.
- 3-second cadence matching `TRADE_INSIGHTS_AI_POLL_SECONDS`.
- Stop on terminal status; fetch `/latest` once to pull full payload; drop interval.
- AbortController on unmount / ticker change.

### 11.4 Run button states

- Idle: `Run`
- Pending: `Running…` (disabled while any provider has a pending analysis_id)
- Cache hit on both: button briefly flashes "Reused" then re-enables

### 11.5 Type generation

After FastAPI changes land, `cd web && npm run gen:types` regenerates `web/lib/types.ts`. No manual TS hand-typing.

## 13. Implementation order

To minimize PR blast radius, ship in two PRs:

**PR-A — schema, API contract, Claude runner (code-complete with both providers default-enabled in code, but dev.sh still on legacy `ai` role):**
1. Migration 053 (schema + indexes)
2. Repository changes (provider field on all reads/writes; provider-filter claim)
3. Shared runners module + extracted Codex runner + new Claude runner
4. API contract changes (POST returns paired stubs; /latest returns keyed dict)
5. Web tabs + per-provider polling
6. All unit + integration tests
7. Config defaults land as policy says (`TRADE_INSIGHTS_AI_ENABLED=true`, `TRADE_INSIGHTS_AI_CLAUDE_ENABLED=true`) — see §7
8. `scripts/dev.sh` keeps the legacy 2-worker `ai` role for this PR (work-stealing across providers, no role split yet)
9. Manual smoke: click Run on TSLA, observe both Codex and Claude rows queue and succeed under the legacy single-pool topology

**PR-B — operational topology split:**
1. Split `scripts/dev.sh` into 2 `ai-codex` + 2 `ai-claude` workers (provider-pinned)
2. Add per-provider heartbeat keys to `worker/scheduler.py` (`trade_insights_ai_tick_codex` / `trade_insights_ai_tick_claude`)
3. Add health-panel per-provider hint env vars (`TRADE_INSIGHTS_AI_CODEX_WORKER_COUNT`, `TRADE_INSIGHTS_AI_CLAUDE_WORKER_COUNT`)
4. Extend `/api/health` JSON with the `trade_insights_ai.codex` / `trade_insights_ai.claude` blocks
5. Manual end-to-end smoke (7-step recipe above) on a live ticker under the new pinned topology

This staging means PR-A is functionally complete (the user can see both tabs on the stock page) under the legacy single-pool worker, with the same throughput. PR-B is a small ops/observability PR that pins workers per-provider and surfaces the per-provider health signal — risk-free to defer if PR-A's behavior is already acceptable.

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| `claude` binary not on PATH in some dev environment | Worker tick catches `FileNotFoundError` and fails the row with a clear message; row visible in `/api/health` queued-depth tells operators to install Claude Code. |
| Claude OAuth keychain not unlocked / expired | Worker fails-fast via the standard non-zero-exit path; `_format_runner_failure` lifts the Claude auth error to the front. Operator runs `claude auth` interactively to refresh. |
| Claude subscription quota exhausted | Mirror of NVDA-quota case for Codex. `_format_runner_failure` lifts the limit message; operator sees the error in the failed-tab body. Run again later or after credit purchase. |
| `--json-schema` enforcement differs subtly from Codex's `--output-schema` (e.g., different "missing field" behavior) | Shared `validate_trade_insights_ai_outcome` re-validates the parsed dict with the same Pydantic model. Any schema-level mismatch raises a Pydantic ValidationError and fails the row with a clean error. |
| `envelope["result"]` field is missing or empty on success | `KeyError` / empty-string check → runner fails the row with `"claude --print result field was missing or empty"`. |
| `provider` column DEFAULT 'codex' backfill is wrong for some historic row | Impossible — all historic rows ARE Codex (the only path that existed). Migration test asserts this. |
| Migration 053 conflicts with an in-flight queued row from before deployment | Backfill defaults the column to 'codex' which matches the runner that would have claimed it; in-flight rows continue to be claimed by the legacy `ai` role (PR-A keeps it). |
| One provider always wins the operator's trust → other becomes shelfware | UI shows both equally weighted (left tab Codex, right tab Claude, identical layout). If desired, defer A/B selection telemetry to a v2. |
