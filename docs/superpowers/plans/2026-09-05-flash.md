# Flash Implementation Plan (argon)

> **For agentic workers:** execute with the user's `/execute-plan` skill, linearly, in this worktree. Do not use subagent-driven-development or parallel dispatch (forbidden by the operator's global CLAUDE.md). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A generic ingest for structured helium agent runs, plus **Flash** — the option-wizard daily brief as a page in argon, sidebar item under Dashboard, grouped by trading week.

**Architecture:** three layers, and only the top one knows what a flash is.
1. **Generic storage** — `uw_scan.agent_runs`, append-only and versioned, keyed by `(tenant, kind, run_day, version_no)` with an idempotency key on `(tenant, run_id)`. `kind` is an opaque tenant-chosen label; `view_jsonb` is a document argon never interprets.
2. **Generic API** — `POST /api/agent-runs` behind a shared bearer token, plus four reads, every one parameterised by `tenant`.
3. **Flash, a view** — `web/app/flash/**` and `web/components/flash/**` read those rows with `tenant=option-wizard`. The five kinds it understands (`premarket`, `intraday`, `close`, `weekly`, `frank`) are a web-layer fact. A second tenant later gets a second view and touches nothing below it.

**Tech Stack:** Python 3.13 / uv, FastAPI, psycopg 3, Postgres (`uw_scan` schema), Next.js 16 / React 19 RSC, TypeScript strict, vitest + Playwright.

**Spec:** `docs/superpowers/specs/2026-09-05-flash-design.md` — **does not exist yet**; Task 11 writes it. Until then §"Target layout" below is the design of record; executors read it in the spec's place.

**Companion plan:** `helium: docs/superpowers/plans/2026-09-05-argon-delivery.md` (branch `feat/argon-delivery`) — the channel that fills this table. **This plan merges and deploys FIRST**, because that channel POSTs to an endpoint that must already exist.

- **The transport is generic; only the view is Flash.** Nothing in `148_agent_runs.sql`, `storage/agent_runs.py`, `models/agent_runs.py` or `api/routers/agent_runs.py` may contain `flash`, `premarket`, `intraday`, `option_wizard`, a ticker, or any options word — except inside a docstring. - **Migration number is 148**, filename `148_agent_runs.sql`. Highest today is `147_fundamentals_desk_rollup.sql`. `scripts/check_migration_prefixes.py` fails on duplicates outside its grandfathered set (037-042, 047, 052-055, 059, 060).
- **Migrations are idempotent and untracked.** No `schema_migrations` table; `scripts/migrate.sh` re-runs every file. `CREATE TABLE IF NOT EXISTS`, `CREATE INDEX IF NOT EXISTS`, and every file opens with `SET search_path TO uw_scan, public;`.
- **`web/lib/types.ts` is generated.** After any FastAPI model change run `npm run gen:types` in `web/` and commit the diff.
- **`tests/integration/api/openapi.snapshot.json` is a contract gate.** New paths and schemas fail `test_openapi_paths_match_snapshot` until it is regenerated in the same commit.
- **Hand-rolled SVG only** (`web/lib/svgChart.ts`). No recharts / d3 / visx. `lightweight-charts` has two documented exemptions; Flash is not one.
- **No synthetic market data.** Every fixture number comes from the recorded option-wizard runs of **2026-09-03**: SPY 772.80, QQQ 717.47, NVDA 227.60, MSFT 510.53, AVGO 355.90, IWM 294.93, 10Y 4.79% (DGS10, 2026-09-01), VIX 16.34 (VIXCLS, 2026-09-01), HY OAS 2.65% (BAMLH0A0HYM2, 2026-09-01). - **Desktop wide, argon dark tokens** (`web/app/globals.css`, recipes in `DESIGN.md`). Inter for prose, IBM Plex Mono for every label, id, timestamp and number. Not email, not mobile.
- **No quantities, no position sizes, no account state on the page.** Per-contract economics only.

### Payoff SVG spec

## Task 1: The `agent_runs` table

**Files:** create `src/uw_scan/storage/migrations/148_agent_runs.sql`.

**Produces:** table `uw_scan.agent_runs`.

**Why generic:** helium is multi-tenant — option-wizard mails a brief, livewire-shepherd heals a pipeline. All produce the same *shape*: a dated run, under a tenant, of some kind, carrying a document only the tenant understands. A `phase` column or a CHECK listing `premarket` would make the second tenant a migration instead of an insert.

- [ ] **Step 1: Write the migration.** Header comment must record: why the table knows nothing about what it holds; why it is append-only and versioned (same discipline as `research_reports`, migration 143 — a re-render publishes N+1 beside N and `code_sha` says which build wrote each); why `run_id` is unique per tenant (that is what makes ingest idempotent for a blind retry); and why `week_key` is stored rather than generated (a Monday review of the week that just ended belongs to that earlier week). **Argon uses the `week_key` helium sends, verbatim** — helium is the only side that knows a run is backward-looking, so the writer decides and the default here is only a fallback (decision 3).

```sql
SET search_path TO uw_scan, public;

CREATE TABLE IF NOT EXISTS uw_scan.agent_runs (
    agent_run_id   bigserial PRIMARY KEY,
    tenant         text NOT NULL,
    kind           text NOT NULL,
    run_day        date NOT NULL,      -- the tenant's own report timezone; never re-derived here
    week_key       text NOT NULL,
    run_id         text NOT NULL,
    version_no     integer NOT NULL,
    code_sha       text NOT NULL,
    schema_version integer NOT NULL,
    outcome        text NOT NULL,
    headline       text NOT NULL DEFAULT '',   -- lifted out so an index need not parse the document
    view_jsonb     jsonb NOT NULL,
    report_jsonb   jsonb NOT NULL DEFAULT '{}'::jsonb,
    created_at     timestamptz NOT NULL DEFAULT now(),
    CONSTRAINT agent_runs_tenant_shape CHECK (tenant ~ '^[a-z0-9][a-z0-9-]{0,63}$'),
    CONSTRAINT agent_runs_kind_shape   CHECK (kind   ~ '^[a-z0-9][a-z0-9-]{0,31}$'),
    CONSTRAINT agent_runs_week_shape   CHECK (week_key ~ '^[0-9]{4}-W[0-9]{2}$'),
    CONSTRAINT agent_runs_outcome_check CHECK (outcome IN ('completed','DEGRADED','FAILED')),
    CONSTRAINT agent_runs_version_positive CHECK (version_no >= 1),
    CONSTRAINT agent_runs_version_uq UNIQUE (tenant, kind, run_day, version_no),
    CONSTRAINT agent_runs_run_uq     UNIQUE (tenant, run_id)   -- idempotency key
);

CREATE INDEX IF NOT EXISTS ix_agent_runs_week
    ON uw_scan.agent_runs (tenant, week_key, run_day, kind, version_no DESC);
CREATE INDEX IF NOT EXISTS ix_agent_runs_latest
    ON uw_scan.agent_runs (tenant, kind, run_day DESC, version_no DESC);
CREATE INDEX IF NOT EXISTS ix_agent_runs_tenant_week
    ON uw_scan.agent_runs (tenant, week_key DESC);
```

Add `COMMENT ON TABLE` / `COMMENT ON COLUMN` for `kind`, `week_key` and `run_id` carrying the three reasons above — the neighbouring migrations all do, and these are the three a later reader will otherwise guess wrong.

**Acceptance:** `scripts/migrate.sh && scripts/migrate.sh` both exit 0, the second silently. `uv run python scripts/check_migration_prefixes.py` exits 0.

def require_ingest_token(
    authorization: str | None = Header(default=None),
    settings: Settings = Depends(get_settings),
) -> None:
    configured = settings.agent_ingest_token
    if configured is None:
        raise HTTPException(503, "agent-run ingest is disabled: UW_SCAN_AGENT_INGEST_TOKEN is not set")

## Task 7: The payoff chart and the gamma bars

**Files:** create `web/lib/flash/payoff.ts`, `web/components/flash/PayoffChart.tsx`, `GammaBars.tsx`; tests `web/tests/unit/flashPayoff.test.ts`, `web/tests/components/flashPayoffChart.test.tsx`.

**Produces:**

```ts
export function intrinsic(right: "call"|"put", strike: number, spot: number): number;
export function pnlAt(legs: Leg[], net: number, spot: number): number;   // per contract; net POSITIVE
export function payoffDomain(a: { strikes: number[]; spot: number; breakeven: number }): [number, number];
export function payoffBreakpoints(a: { strikes: number[]; breakeven: number;
                                       domain: [number, number] }): number[];
```

**Why argon re-derives this** instead of trusting the `pnlAt` points the view already carries: those are five percentage offsets — enough for a smooth curve, not enough to place the kinks. The payoff is piecewise linear with kinks exactly at the strikes, so evaluating at the strikes gives the true shape with five points instead of a hundred, and a corner sitting a pixel off the strike it is labelled with is worse than no chart. The re-derivation reads **legs and net only** — never a model-written price.

```
pnl(S)          = 100 * ( Σ_legs sign * ratio * intrinsic(right, K, S) − net )
                  sign = +1 for buy, −1 for sell
intrinsic(put)  = max(K − S, 0);   intrinsic(call) = max(S − K, 0)
domain          = [lo − 0.18*(hi − lo), hi + 0.18*(hi − lo)]  over {strikes} ∪ {spot, breakeven}
breakpoints     = sort(unique([domainLo, ...strikes strictly inside, breakeven, domainHi]))
y-domain        = [−maxLoss − 0.08*(maxGain + maxLoss), maxGain + 0.08*(maxGain + maxLoss)]
```

`PayoffChart({ candidate })` renders `null` when `pricing.kind !== "priced"`, when either bound is `null` (unbounded has no y-domain, and inventing one draws a ceiling the position does not have — for this tenant that is a data fault, not a shape), or when spot or breakeven is missing. Everything else follows §"Payoff SVG spec" exactly. The `aria-label` derives its prepositions from `pnlAt(legs, net, domainLo) > pnlAt(legs, net, domainHi)` rather than hard-coding *above*/*below* — a put debit spread gains below its breakeven, a call debit spread above it.

`GammaBars({ ticker, spot, levels })` follows §"Gamma bars" exactly.

## Decisions

**Settled — implement as written.**

1. **The `weekly` phase stays at Sunday 08:00 ET.** helium's `tenant.yaml` fires it at `0 20 * * 0` Asia/Hong_Kong, and it is not moving: Sunday is after Friday's close by every measure that matters, it gives the writer the weekend's news, and moving a live launchd trigger gains nothing. **Argon's copy changes instead** — the Outlook empty state reads `Generated Sunday morning`. Applies to §"Target layout" and Task 9.
2. **`week_key` is sent by helium and argon uses it verbatim.** helium computes it per kind — the previous ISO week for `frank`, the ISO week of `run_day` for everything else — because helium is the only side that knows a run is backward-looking. Argon keeps its `iso_week_key(run_day)` fallback for a writer that omits the field, but that path is not exercised by option-wizard. Applies to Tasks 1, 2 and 3.

**Standing recommendations — not blockers, revisit only when one has caught something (doctrine: ceremony must earn its keep).**

3. **Flash shows only the newest version of a run.** The table keeps every version and the API accepts `?version=`, but nothing re-renders a past day today, so a version picker would be a control that never changes anything. Storage keeps the option open at zero cost.
4. **Argon does not validate the view's shape at ingest.** Validating would couple the transport to the tenant, and a helium deploy that adds a field would fail at argon's door instead of rendering one section short. `schema_version` plus a reader that says which version it understands is the check that earns its keep.
5. **The ingest token is shared, not per-tenant.** The realistic threat is a misconfigured laptop, not a hostile Tailnet peer. Per-tenant tokens earn their keep the day a tenant runs somewhere helium does not control, at which point the thing to add is an `agent_runs.written_by` column, not a second auth scheme.

## Deploy to the mini

Argon runs on the Mac mini (`macmini`, user `moremeds`) as **Docker containers**, not launchd — the 14 application plists were retired 2026-07-08. Authority: `docs/runbooks/docker-deploy.md` (topology and rollback) and `docs/runbooks/release.md` (how a release is cut). `docs/superpowers/plans/2026-08-30-release-fast-safe.md` is the *plan* that produced that runbook, not an operational guide.

**The path is: merge to `main` → cut a version tag → GHCR images → the engine-wide Watchtower recreates the services → the `api` container self-migrates on start.**

### 1. Land and release

```bash
# On a clean, current local main, with the CHANGELOG entry merged:
scripts/release/cut.sh prepare patch        # opens a release/vX.Y.Z PR
# merge that PR, return local main to the exact origin/main merge commit, then:
scripts/release/cut.sh tag                  # waits for that SHA's green push-CI, then tags
```

Do not cut another tag while a Release workflow is running or queued. A green Release workflow means **artifacts are published, not that production has them** — GitHub Actions cannot reach the private mini.

### 2. Migration 148 applies itself

The `api` service's command is `migrate_runner && exec uvicorn`, so a Watchtower image update runs pending migrations before serving. **No manual step is required for 148.** If you need to apply it out of band (a migration-only change, or Watchtower has not fired):

```bash
ssh macmini
export PATH=/opt/homebrew/bin:$PATH
cd /opt/argon && docker-compose --profile migrate run --rm migrator   # idempotent
```

### 3. Add the ingest token

`UW_SCAN_AGENT_INGEST_TOKEN` must be in **`/opt/argon/.env`** on the mini — the compose services read it through `env_file: [/opt/argon/.env]`. It is not in either repo.

```bash
ssh macmini
# generate once; the SAME value goes into helium's ~/.config/helium/helium.env
openssl rand -hex 32
# append UW_SCAN_AGENT_INGEST_TOKEN=<that value> to /opt/argon/.env, then:
cd /opt/argon && docker-compose up -d api web
```

An `.env` change is **not** picked up by a Watchtower image recreate on its own — `up -d` is what re-reads it.

> `compose.yml` changes are not auto-deployed either. This plan adds no compose change; if one ever becomes necessary, mirror the repo file to `/opt/argon/compose.yml` by hand, as the runbook says.

### 4. Verify

```bash
ssh macmini
# a) the API is serving the new version against a live DB
curl -s http://127.0.0.1:8400/api/health | jq '{version, db, active: .ws_consumer.active_source}'
#    want: version == the tag you cut, db == "up", active_source == "xenon_ws"

# b) the table exists with both unique constraints and three indexes
docker-compose -f /opt/argon/compose.yml exec -T api \
  psql "$DATABASE_URL" -c '\d uw_scan.agent_runs'
#    ^ if the api image has no psql, run the same \d from the host's own psql
#      against the same DB. Which of the two is correct here is NOT documented
#      in the repo — confirm with the operator.

# c) ingest refuses an unauthenticated write
curl -s -o /dev/null -w '%{http_code}\n' -X POST http://127.0.0.1:8400/api/agent-runs \
  -H 'Content-Type: application/json' -d '{}'
#    want: 401.  A 422 means the auth dependency is not ahead of body validation — fix that first.
#    A 503 means UW_SCAN_AGENT_INGEST_TOKEN did not reach the container (step 3).

# d) the reads answer
curl -s 'http://127.0.0.1:8400/api/agent-runs/weeks?tenant=option-wizard' | jq
#    want: 200 with {"tenant":"option-wizard","weeks":[]} before helium has posted anything

# e) SSR renders the page, and the client-side /api/* rewrite proxies web -> api
curl -sfo /dev/null -w '%{http_code} /flash\n' http://127.0.0.1:3001/flash
curl -s http://127.0.0.1:3001/api/health | jq '{via_web_rewrite: .db, version}'
#    want: db == "up", NOT a 500 / HTML error page. SSR page codes stay green even
#    when this is broken, because the rewrite target is BAKED at image build.
```

Then open argon in a browser on the Tailnet and check the sidebar entry, the redirect, the week strip pips, and that a day with no run says `NO RUN RECORDED`. Full content verification needs a real helium run — that is the companion plan's "Deploy to the mini" section.

### 5. Rollback

**Watchtower has no rollback for a bad image.** Roll back by retagging the previous good version as `:latest` in GHCR and letting Watchtower recreate, or by pinning the previous tag in `/opt/argon/compose.yml` and running `docker-compose up -d`. The exact retag command is not written down in this repo — **confirm with the operator before you need it.**

Migration 148 is additive and creates only new objects, so a code rollback leaves the table in place harmlessly. There is no down-migration; the repo has no down-migration mechanism at all.
