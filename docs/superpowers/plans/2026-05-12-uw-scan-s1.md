# S1 — Single-Stock Card Implementation Plan

> Slice-specific plan for Slice 1 of `docs/superpowers/plans/2026-05-11-uw-scan-rebuild-plan.md`. S0 findings (`docs/uw-samples/README.md`) are pre-loaded into the contracts below — do not re-research.

**Goal:** Streamlit page accepting a ticker → fetches ~16 UW endpoints → persists raw + audit + typed → assembles a `SingleStockReport` matching the spec's Card → renders it. Snapshot save → reload → semantically-equivalent render.

**Setup type:** C (Deep Conviction) only. F/A/E land later.

---

## S0-Adjusted Contracts (load-bearing — do not re-derive)

These nuances were nailed down in S0 and MUST shape S1's models / normalizers:

1. **Time-series endpoints**: `iv_rank`, `volatility_stats`, `realized_volatility`, `skew` all return arrays of daily rows wrapped in `{"data": [...]}`. Normalizers pick the latest row (max `date`) for the Card's "current" value AND persist the full series.
2. **Flow alerts pagination**: cursor-based via `newer_than` / `older_than` keys — NOT `next_page`/`has_more`/`page`/`total`. Don't build a generic paginator that assumes those keys.
3. **`short_data` lacks short-interest %**: only `short_shares_available`, `fee_rate`, `rebate_rate`. The Card's "Short Int %" field is **deferred** in S1 — render as "n/a (UW endpoint does not expose %)" with a clear note. Do not invent a derivation.
4. **`option_contracts_by_symbol`** is the same path as `option_contracts` with `option_symbol[]` query param. S1 uses the broad probe for the contract surface and the by_symbol form for trade-plan exact strike pricing.
5. **Rate-limit budget**: 20000/day, ~120/min. Client honors `x-uw-req-per-minute-remaining` proactively (sleep if < 5 remaining); falls back to 429 retry-with-backoff.
6. **`x-uw-req-per-minute-reset` unit**: unconfirmed. Treat as seconds; if 429 is hit, log the header value and the actual time to next success — S6 reconciles.
7. **Bulk screener**: `/api/screener/stocks` is for S2. Don't wire into S1.

## Files (cumulative, S1 only — first time these exist)

### Source — `src/uw_scan/`
- `__init__.py` — empty
- `config.py` — Pydantic `Settings` from env; fields: `api_key`, `db_host/port/name/schema/user/password`, `max_requests_per_minute=110` (under UW's 120 with margin), `request_timeout_seconds=30`. Raises on missing `api_key` — no fallback to empty string.
- `models.py` — All Pydantic v2 models. **Field names match the actual API payload keys** (verified against `docs/uw-samples/`). Models:
  - `FlowAlert`, `IvRankRow`, `VolStatsRow`, `RealizedVolRow`, `TermStructureRow`, `InterpolatedIvRow`, `SkewRow`, `GreekExposureRow`, `SpotExposureRow`, `GreeksRow`, `OiPerStrikeRow`, `OiChangeRow`, `MaxPainRow`, `OptionContractRow`, `DarkPoolPrint`, `ShortDataRow`
  - Aggregates: `MarketStructure`, `VolatilityProfile`, `FlowSnapshot`, `VRPAssessment`, `TradePlan`, `SingleStockReport`
  - All use `Decimal` for prices/premiums; UW returns strings, normalizer casts.
- `api/__init__.py` — empty
- `api/client.py` — `UwClient` wraps `httpx.Client`. Reads `x-uw-*` rate-limit headers on every response, sleeps proactively. Raises typed `UwHTTPError` (with status, endpoint, response excerpt) and `LiveDataUnavailable` (when API key missing / network down). Logs `x-uw-daily-req-count` per request. No silent fallbacks.
- `api/endpoints.py` — `class Endpoint(StrEnum)` with one entry per endpoint slug. Each entry stores path + required-params list (so callers can't forget). Mirrors `scripts/s0_probe_endpoint.py`'s ENDPOINTS dict in structure.
- `sources/__init__.py` — empty
- `sources/uw.py` — High-level fetchers `fetch_iv_rank(ticker, client, ...)`, etc. Each:
  - Calls `client.get(...)`
  - Persists raw response to `raw_payloads` + audit row to `api_request_audit` BEFORE returning
  - Returns typed Pydantic model (single value for "current state" endpoints; list for series)
  - On any normalizer failure, raises `NormalizationError` with the failing JSON path — no silent skipping
- `normalize.py` — Pure functions `normalize_<slug>(raw_payload: dict) -> Model`. Latest-row selection is explicit (`max(rows, key=lambda r: r["date"])` etc.). **No field-name fallback chains** (no `r.get("price") or r.get("p") or r.get("close")`). Single key lookup, KeyError on miss.
- `storage/__init__.py` — empty
- `storage/repository.py` — `Repository` class taking a `psycopg.Connection`. Methods: `insert_scan_run`, `insert_audit_row`, `insert_raw_payload`, `insert_*_rows` for each typed table. No fake cursor abstraction. Persists with explicit columns (no `**kwargs` splatting from arbitrary dicts).
- `storage/migrations/001_s1_core_tables.sql` — Creates schema `uw_scan` + all 20 S1 tables with explicit column comments on every date/timestamp column. Multi-valued columns use `TEXT[]` (not pipe strings). One file, idempotent (uses `CREATE TABLE IF NOT EXISTS`).
- `scoring.py` — `classify_setup_c(report) -> SetupClassification | None` for Deep Conviction (criteria: net premium > $5M, IV rank > 70 OR < 30 for direction, dark pool size > $X). Returns None if criteria not met. **Returns a typed object, not a magic string.**
- `reports/__init__.py` — empty
- `reports/single_stock.py` — `assemble_single_stock_report(ticker, run_id, repo) -> SingleStockReport`. Pure function — reads from persisted tables (not from live API). This makes "save snapshot → reload" trivial.
- `pipeline.py` — `run_single_stock(ticker, client, repo) -> SingleStockReport`:
  1. `run_id = repo.insert_scan_run(...)`
  2. Sequential fetches with `sources.uw.*` — each persists raw + audit + typed
  3. `assemble_single_stock_report(ticker, run_id, repo)` — pulls back, builds report
  4. Score + classify, persist `opportunity_scores` + `structure_ideas`
  5. Return report

## Exit Gate (from master plan, expanded)

1. `uv run pytest tests/unit/ tests/integration/` passes.
2. `uv run streamlit run app/streamlit_app.py` launches; TSLA renders 6 Card sections (header, market structure, volatility, flow, VRP, trade plan).
3. Row counts after one live TSLA run (asserted by `test_pipeline_e2e`):
   - `scan_runs ≥ 1`
   - `raw_payloads ≥ 16`
   - `api_request_audit ≥ 16`
   - `flow_events ≥ 1`
   - `iv_rank_history = 1` (latest row only) OR `≥ 1` (full series — see decision below)
   - `volatility_stats_history ≥ 1`, `realized_volatility_history ≥ 1`, `iv_term_snapshots ≥ 1`, `interpolated_iv_snapshots ≥ 1`, `risk_reversal_skew_history ≥ 1`
   - `greeks_by_expiry_strike ≥ 1`, `exposures_by_expiry_strike ≥ 1`
   - `oi_by_strike ≥ 1`, `oi_change_events ≥ 1`, `max_pain_by_expiry ≥ 1`
   - `option_contract_snapshots ≥ 1`, `dark_pool_events ≥ 0` (≥ 1 if TSLA had prints; on TSLA it always does), `short_interest_snapshots = 1` (only one short_data row persisted per run — that's the latest snapshot)
   - `opportunity_scores ≥ 1`, `structure_ideas ≥ 0` (≥ 1 if type C classified — Card always proposes at least the bull-call-spread sketch)
   - `option_surface_snapshots = 0`, `oi_by_expiry = 0` (S6 fills these — explicit zero assertion to catch regression)
4. Snapshot save (`run_id`) → reload (`assemble_single_stock_report` against that run_id) produces semantically equivalent render.
5. Guardrails: ruff clean, AST except check clean, CI grep checks clean.

**Decision**: S1 persists the FULL TIME SERIES for `iv_rank`, `volatility_stats`, `realized_volatility`, `skew` (not just the latest row). This costs negligibly more storage and saves a refetch for VRP charts. So row counts above are `≥ 1` for each.

## Risks

- **Postgres timestamp/date column semantics**: easy to confuse `market_date` (the trading date the data refers to) with `inserted_at` (DB write time). Migration adds `COMMENT ON COLUMN` for every such column.
- **Time-series persistence on every run could duplicate rows**: use unique constraints `(ticker, date)` on history tables so re-runs UPSERT, not duplicate.
- **Streamlit reruns mid-pipeline**: Streamlit's execution model reruns the script on every interaction. Guard the live pipeline behind explicit button press; cache `client` and `repo` connections with `@st.cache_resource`.
