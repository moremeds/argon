## Notes / decisions

- Schema fields are `.optional()` in zod and the default (`"1y"`, compact
  field set) is applied in the handler — `McpTool`'s handler signature takes
  `z.infer` of the *input* schema, so a `.default()` there wouldn't be visible
  to direct `tool.handler(args, ctx)` callers (which is how the tests drive
  it); the schema would also mis-type defaulted keys as required. Optional +
  handler default is the honest encoding.
- `data !== eod` is the merge-detector: `mergeLiveHead` returns the same
  object reference when the live head is absent/stale, a new `{...data}`
  when fresh — verified in `series.ts` (`return data` vs `return {...data}`).
- `fvg_nearest` distance is to the gap band (0 when last close sits inside),
  not to an edge midpoint.
- Bundle-purity covers all four B-owned tools per the contract, including the
  three stubs.

payload — placeholder symbols and real values under the wrong ticker are both
banned. Fixed on top, nothing else touched:

- `(g)` now uses only AAPL/NVDA/SPY. A single scan's per-ticker GETs are
  sequential (`loadTicker` awaits EOD → live → magnets), so 3 tickers alone
  peak at 3 in flight — the lead's "3 GETs × 3 tickers = 9 in flight" only
  holds if the requests overlap, which they can't inside one scan. The rewrite
  runs **three concurrent `tool.handler` calls** over the 3 real tickers with
  a `magnet_*` field: the module-level pool is shared, so 9 cold-cache
  pipelines push >8 requests through it. Asserts `maxInflight === 8`, all 9
  rows error-free, `eodGets === 9`, `magnetGets === 9`, and `keyCalls === 1`
  (the single-flight key check holds under the concurrent fan-out).

  tasks (no symbols, no market data): cap binds at the limit, waiters start
