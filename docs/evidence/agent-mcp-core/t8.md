# Task 8 — read-only trade-insights preview route

Baseline: `feat/agent-mcp-core` @ `37f05b33` (task 7). Goal: give the MCP a
GET that returns the assembled Trade Insights body WITHOUT the
snapshot/candidates writes, so `/stock/{ticker}/trade-insights` can stay
denylisted while agents still read it.

## Changes

- `src/uw_scan/api/routers/trade_insights.py`
  - Split `_build_and_persist_trade_insights`: new `_build_trade_insights`
    does 404 + `assemble_single_stock_report` + `assemble_trade_insights` and
    returns `(response, payload)`; the persist wrapper calls it then does the
    unchanged upsert/replace (`run_id` re-read inside the same txn — identical
    value). GET `/trade-insights` and POST `ai-analysis` call sites and
    behaviour are byte-for-byte the same.
  - New `GET /stock/{ticker}/trade-insights/preview`
    (`response_model=TradeInsightsResponse`) calls `_build_trade_insights`
    only — no upsert, no replace, no commit. Registered directly after the
    persisting GET; `preview` vs `ai-analysis/{analysis_id}` are distinct
    literal segments — no routing ambiguity.
- `tests/integration/api/test_trade_insights_ai_endpoint.py`
  - `test_trade_insights_preview_is_read_only`: seeds a TSLA run, counts
    `trade_insight_snapshots` + `trade_insight_candidates` before/after
    `/preview` (unchanged), asserts `preview.json() == persisted.json()` for
    the same fixture, then shows the persisting GET did write (+1 snapshot).
  - `test_trade_insights_preview_404_without_runs`: unseeded ticker → 404.
- `tests/integration/api/openapi.snapshot.json` — surgical insert only:
  43 added lines, the `preview` path block in route-registration position
  (verified: paths otherwise identical, `components` byte-equal).
- `web/lib/types.ts` — `npm run gen:types` regeneration, +53 lines (the new
  `GET` entry only).
- `web/mcp/lib/endpoints.ts` — DENYLIST unchanged:
  `/stock/{ticker}/trade-insights` stays denied; `/preview` is allowlisted
  automatically via the OpenAPI-derived list.
