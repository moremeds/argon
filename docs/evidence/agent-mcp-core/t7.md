# Task 7 — Astra review fixes (read-only hardening + event hub)

Baseline: `feat/agent-mcp-core` @ `3f5bd11a` (A+B+C merged). Six findings fixed
on top, one commit.

## 1. Mutating GET denied

`GET /stock/{ticker}/trade-insights` builds AND persists a snapshot —
`src/uw_scan/api/routers/trade_insights.py` `get_trade_insights` calls
`_build_and_persist_trade_insights(...)` and `repo.conn.commit()`. A GET that
writes cannot sit on a read-only allowlist → added to `DENYLIST` in
`web/mcp/lib/endpoints.ts` (with a comment naming the commit call). Audit of
other routers: no other `@router.get` commits (`rg -l 'def get_'` × `commit`
inside GET handlers — only this one).

Test: `parseOpenApiEndpoints` filters the denylisted template even when the
doc advertises it (`mcpReadEndpoints.test.ts`).

## 2. `read` path validation hardened

`badPath` now also rejects `\` (WHATWG folds it to `/`), `?`, `#`, and control
chars `<0x20` / `0x7f`, on top of the existing `%`, `//`, `.`/`..` segment
checks. Placeholder values still reject `.`/`..` and go through
`encodeURIComponent`. New cases: `/stock/..\health`, `/stock/AAPL?x=1`,
`/stock/AAPL#f`, `\n/\r/\t/\x00/\x1f/\x7f` — all rejected before the openapi
fetch (`getSpy` never called).

Defense-in-depth added in `makeApiGet` (`server.ts`): after building the URL,
`url.pathname !== "/api" + path` → throw before fetch. Verified by node:
`/stock/../x`→`/api/x`, `..\\`→`..`/`/` fold, `?`/`#` truncate, `/%2e%2e/x`
collapses — each now throws `normalization mismatch` and fetch is never
called.

## 3. Revocation re-check before each SSE event

`send` in the GET/SSE branch queries
`SELECT 1 FROM uw_scan.mcp_token WHERE label = $1 AND revoked_at IS NULL`
before every push. Empty → the event is dropped, `unsubscribe?.()` runs, and
`session.transport.close()` fires `onclose` → session deleted. Vitest:
initialize → SSE GET → event 1 delivered (`argon_event` frame on the wire) →
label revoked → event 2 → unsubscribe called + follow-up POST on the session
→ 404.

## 4. One shared LISTEN client (no per-subscriber pool checkout)

`events.ts` rewritten as a module-level hub: lazily `ctx.db.connect()` once,
`LISTEN mcp_event`, each `notification` → one `SELECT` → in-process fan-out to
all subscribers. `unsubscribe` removes only that subscriber; when the last
leaves, `UNLISTEN` + `release()` and the hub is dropped (choice documented in
the header comment — no idle connection held when nobody listens). Client
`'error'` → every subscriber's `close()` fires + `release(err)`; next
subscribe starts a fresh hub (reconnect stays the client's job, per spec).
`resetEventsHubForTests()` exported for vitest isolation.

`web/tests/unit/mcp/events.test.ts` rewritten for the hub: 1 connect for 2
subs, fan-out with a single SELECT, partial unsubscribe keeps the hub, last
unsubscribe → UNLISTEN+release, error closes all streams, fresh hub after
teardown, idempotent unsubscribe.

Also: main pool now gets `connectionTimeoutMillis: 5000` so a wedged Postgres
fails connect fast instead of queueing.

## 5. Disconnect during subscribeEvents

`res.on("close")` is registered BEFORE `await subscribeEvents`. `resClosed`
flag + `if (resClosed) unsubscribe?.()` after the await — a client that hangs
up mid-setup leaves no subscriber behind. Vitest: abort the SSE fetch while
the injected hook is gated → resolve → unsubscribe called exactly once.
`subscribeEvents` is injectable via `HandlerOptions` (defaults to the real
hub) for these tests.

## 6. Runbook order

`docs/runbooks/agent-mcp.md` §3 reordered: deploy/migrate → `\dt
uw_scan.mcp_*` → `psql -v ON_ERROR_STOP=1 -f scripts/ops/mcp_role.sql` →
`has_table_privilege` checks (incl. `INSERT watchlist` must be `f`). §5 notes
revocation now also kills a live SSE stream on the next event.
